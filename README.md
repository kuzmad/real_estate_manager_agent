# 🏢 Real Estate Manager Agent

Мультиагентная система на базе LangGraph для управления коммерческой недвижимостью. Агент помогает отвечать на юридические вопросы по договорам аренды, выполнять финансовые расчёты, вести историю взаимодействия с арендаторами и поддерживать свободный диалог.

## 🎯 Возможности

- **Юрист** — отвечает на вопросы по договорам аренды через RAG (поиск по векторной базе PDF-документов)
- **Финансист** — выполняет расчёты доходности и налогов по УСН с помощью инструментов (Tools)
- **Менеджер объектов** — ведёт историю взаимодействия с арендаторами с автоматической суммаризацией
- **Ассистент** — поддерживает свободный диалог и плавно переключается на рабочие вопросы
- **Параллельная маршрутизация** — если запрос содержит и small talk и рабочий вопрос, оба агента отвечают одновременно через `Send`
- **Персистентная память** — история диалогов сохраняется между сессиями через AsyncSqliteSaver
- **Streaming** — ответы передаются в реальном времени через FastAPI + StreamingResponse

## 🏗️ Архитектура

```
Запрос пользователя
        │
        ▼
work_small_talk_node  ←  определяет тип запроса (work / small talk / оба)
        │
        ├── Send("router_node")      ←  рабочий вопрос
        │         │
        │         ├── lawyer_node         (RAG по договорам)
        │         ├── financial_node      (Tools + ReAct)
        │         └── tenant_extractor_node → property_manager_node
        │
        └── Send("assistant_node")   ←  small talk
        │
        ▼
combiner_node  ←  объединяет ответы в единый текст
        │
        ▼
    Ответ пользователю
```

## 🚀 Быстрый старт

### 1. Клонируй репозиторий

```bash
git clone https://github.com/kuzmad/real_estate_manager_agent.git
cd real_estate_manager_agent
```

### 2. Создай виртуальное окружение

```bash
python -m venv venv
source venv/bin/activate  # macOS/Linux
venv\Scripts\activate     # Windows
```

### 3. Создай `.env` файл

```env
OPENAI_API_KEY=your_api_key_here
```

### 4. Загрузи договоры в векторную базу

Положи файлы договоров в папку `contracts/` и запусти:

```bash
python rag/loader.py
```

### 5. Запусти приложение

```bash
honcho start
```

Открой браузер: [http://localhost:8501](http://localhost:8501)

## ⚙️ Конфигурация

Все параметры задаются через `.env` или переменные окружения:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `OPENAI_API_KEY` | — | API ключ OpenAI |
| `PROXY_BASE_URL` | `https://openai.api.proxyapi.ru/v1` | URL прокси |
| `DEFAULT_MODEL` | `openai/gpt-5.4-nano` | Модель LLM |
| `MAX_HISTORY_MESSAGES` | `4` | Порог суммаризации истории |
| `MAX_TENANT_HISTORY` | `6` | Порог суммаризации по арендаторам |
| `TENANTS` | `ozon, hemotest, wildberries` | Список арендаторов |

## 🔑 Ключевые технические решения

**Параллельная маршрутизация через `Send`**
Если запрос содержит и рабочий вопрос и small talk — оба агента запускаются параллельно, результаты объединяются в `combiner_node`.

**Память по арендаторам**
`property_manager` автоматически определяет арендатора из текста запроса и хранит историю отдельно для каждого в `tenant_history`. При превышении порога — история суммаризируется через LLM.

**Инициализация графа через lifespan**
Граф и соединение с SQLite создаются один раз при старте FastAPI приложения через `@asynccontextmanager lifespan`, а не при каждом запросе.

**Streaming через `stream_mode="messages"`**
FastAPI возвращает `StreamingResponse`, LangGraph передаёт `AIMessageChunk` по мере генерации токенов.
